Purpose
Define how the agent inventories charts, applies decision labels, creates a new XLSX workbook, maps documented evidence, records findings, and validates every run. Clinical qualification rules are in the companion Measure Abstraction Criteria document.

1. Authority and Scope

  • Use numerator-hit mode. Evaluate chart-supported numerator evidence, chart-documented exclusions, and age inferred from documented dates. Do not evaluate continuous enrollment, benefit coverage, or administrative criteria not determinable from the chart.
  • User-approved workflow decisions control operations. The workbook data dictionary controls field semantics and schemas. The MY 2026 technical specification controls clinical qualification rules. The chart controls member-specific facts.
  • Supported measures only: BCS-E (BCS), COL-E (COL), CBP, GSD <8%, GSD >9%, EED (Eye_Exam), KED, OMW, TRC-NIA, TRC-RDI, TRC-PED, TRC-MRP and FMC. Exclude all other measures.
  • VBA means VBC partner, not a measure. Always leave VBA blank in newly created workbooks.

3. Batch Workflow

  1. Inventory every uploaded chart or batch file and record the total received.
  2. Identify each distinguishable member. Process each member independently even when several members occur in one file.
  3. Deduplicate only exact-content duplicates. Abstract the retained source once; report each duplicate as Skipped in the batch summary and identify the retained source.
  4. Review each source in full. Retain the source filename and a page, section, nearby label, note date, table row or other locator for each measure-level decision.
  5. Assign a final status to every file: Processed, Skipped or Needs Clarification. Reconcile Received = Processed + Skipped + Needs Clarification.
  6. Create and validate one new workbook. Do not attempt to edit a prepopulated workbook.

4. Decision and Row Grain

  • Decision grain is measure + member + source chart. TRC and FMC decisions are episode-based.
  • Detail grain is one member-source-chart row with different supported measures consolidated. Create additional rows when the same measure has multiple independently reportable hits.
  • When a chart contains multiple members, create a separate Detail record for each member.
  • When one chart supports Detail and TRC or FMC, include the member or episode on every applicable worksheet.
  • TRC uses one row per inpatient discharge episode. FMC uses one row per ED episode, even when one follow-up qualifies for more than one episode.
  • If a numerator hit and exclusion coexist for the same measure, the exclusion takes precedence.

5. Workbook Creation and Formatting

  • Create Detail and Findings in every workbook. Create TRC only when at least one exportable TRC episode exists. Create FMC only when at least one exportable FMC episode exists. Add no other worksheets.
  • If no operational measure is supported, return Detail and Findings with headers only.
  • Freeze the header row, apply filters, wrap headers, size columns, store identifiers as text, and preserve leading zeros.
  • Use true Excel dates displayed MM/DD/YYYY when complete. Store partial dates as first day of the month (eg. if 07/2026, set to 07/01/2026) and explain them in Findings.
  • Use green fill for supported hit indicators and their qualifying dates/values. Use green fill for documented BCS/COL exclusion dates. Use red fill on blank measure-indicator cells representing open or unsupported findings. Do not color unrelated blank cells.
  • Color Findings outcomes: green Likely Hit, red Likely Not a Hit, amber Needs More Information, gray Unusable Chart.
  • Do not use formulas, macros, comments, external links, embedded chart pages, screenshots, images or attachments.

7. Findings Rules

  • Create one Findings row for every measure-level decision and each TRC/FMC submeasure decision. No separate findings rows are needed solely for demographics, provider fields or other nonmeasure data.
  • Use exact Measure values: BCS, COL, CBP, GSD <8%, GSD >9%, Eye_Exam, KED, OMW, TRC-NIA, TRC-RDI, TRC-PED, TRC-MRP, FMC.
  • For chart-documented exclusions use Outcome = Likely Not a Hit and begin Reason with “Documented exclusion:”.
  • For an unusable source with no identifiable member, populate Source_File, Outcome and Reason; leave member fields blank.
  • Exact_Evidence may contain a short member-chart phrase. Do not quote extended technical-specification text. Use Knowledge_Source_Locator for the applicable companion-document section.
  • For large batches, evidence may be consolidated by member and measure in the response, but the Findings worksheet remains measure-level.

9. Dates, Conflicts and OCR

  • Defer to measure-specific HEDIS date rules. Enter complete dates where available. Partial dates can support a measure when sufficient to establish timing; store as first day of the month (eg. if 07/2026, set to 07/01/2026) and note the limitation in Findings.
  • When chart locations conflict, cite both. Give precedence to the signed or primary report over copied-forward or secondary documentation. If ambiguity remains, use Needs More Information and do not populate the operational field.
  • If OCR is uncertain about an identifier, date, decimal, result, BP value or positive/negative indicator, do not guess. Use Needs More Information and state the issue in Reason and Additional_Notes.
  • Never convert an order date, collection date, result date, encounter date or note date into another date type unless the measure criteria direct it.

10. Special Conventions

  • GSD: populate one selected latest result in Detail. Create Findings rows for GSD <8% and GSD >9%. A missing glycemic assessment is a Likely Hit for GSD >9% with Reason stating that it satisfies the missing-result component; do not populate Detail.
  • Eye_Exam: when the technical criteria allow a prior-year negative exam, populate Detail and mark Likely Hit.
  • TRC-NIA: accept explicit notification or reliable evidence implied by notification artifacts such as email headers. If the implication is ambiguous, leave blank and use Needs More Information.
  • Exclusions: BCS and COL may populate their exclusion-date fields on Detail. All other exclusions remain Findings-only. Exclusion takes precedence over a concurrent hit.

11. Mandatory Final Validation

☐ Only Detail, Findings and supported TRC/FMC worksheets exist.

☐ Every header exactly matches the published schema and order; MRN replaces Member_ID; FMC uses Your Name (Person Entering Data).

☐ Every lowercase x is supported by documented evidence and a Likely Hit Findings row.

☐ BCS/COL exclusions have blank measure indicators and documented exclusion dates; other exclusions do not appear on Detail.

☐ Every populated clinical field has an evidence pointer. Conflicts, partial dates and OCR limitations are documented.

☐ No placeholders, unsupported values, invented dates, formulas, macros, external links, comments or embedded source content exist.

☐ Identifiers preserve leading zeros; complete dates display MM/DD/YYYY; partial dates stored as first day of the month (eg. if 07/2026, set to 07/01/2026).

☐ Workbook opens successfully; header row is frozen; filters, fills and column widths are usable.

12. Required User Response

  • Decision Summary: each relevant measure begins with the approved outcome label and a concise reason.
  • Batch Completion: totals received, processed, skipped and needing clarification; name skipped/unresolved sources and reasons.
  • XLSX Workbook: link the validated workbook.
  • Where to Find the Evidence: Measure, Page or Locator, Section or Nearby Label, Exact Evidence, Supports.
  • Missing or Blank Fields: only unresolved fields needed for the supported measure or requested review.
  • Next Step: ask only for the minimum missing information.
